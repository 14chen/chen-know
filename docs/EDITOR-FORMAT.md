# 富文本格式与笔记交互 · 本轮冻结契约

> 来源：用户使用反馈 4 条。
> 决策（用户已拍板）：**Markdown 原生 + 内联 HTML**；编辑器宽度 **860px + 提供宽屏切换**。

## 1. 四条反馈的结论（已取证，勿重新论证）

|---|---|---|

## 2. 富文本的**存储格式**（唯一真源，四方必须一致）

| 工具栏按钮 | 存储到正文的语法 | 现有渲染 | 谁需要改 |
|---|---|---|---|
| 加粗 | `**文字**` | ✅ 已有 | — |
| 斜体 | `*文字*` | ✅ 已有 | — |
| 删除线 | `~~文字~~` | ✅ 已有 | — |
| 行内代码 | `` `文字` `` | ✅ 已有 | — |
| 链接 | `[文字](url)` | ✅ 已有 | — |

| **文字颜色** | `<span style="color:#e11d48">文字</span>` | ❌ 需新增 | p-editor |

**调色板**（固定，写死成常量，不要自由取色 —— 保证产出的 HTML 干净、可预期）：

```
文字颜色：#e11d48(红) #ea580c(橙) #ca8a04(黄) #16a34a(绿) #2563eb(蓝) #7c3aed(紫) #475569(灰)
背景颜色：透明(清除) #fee2e2 #ffedd5 #fef9c3 #dcfce7 #dbeafe #ede9fe #f1f5f9 + #e5e7eb(深一档)
```

**颜色一律用 `#rrggbb` 小写**（不用 `rgb()` / 颜色名），保证导出稳定。

## 3. 渲染要求（p-editor）

live preview 必须把上述内联 HTML **渲染成真实样式**，而不是显示源码：

- `<mark>文字</mark>` → 黄底
- `<u>文字</u>` → 下划线
- `<span style="color:#e11d48">文字</span>` → 对应文字色
- `<span style="background-color:#fef08a">文字</span>` → 对应底色

**要求**：

1. **沿用既有的 Typora 行为**：光标所在行显示源码，光标移开渲染。内联 HTML 与既有 Markdown 装饰**必须共存**（例如 `**<u>粗体下划线</u>**`）。
2. **嵌套**：至少支持「Markdown 包 HTML」与「HTML 包 Markdown」两种顺序。
3. **不认识的属性/标签一律不渲染**（保持原样显示源码），**绝不执行脚本**、绝不 `innerHTML` 注入字符串 —— 必须走 DOM 构造（第二轮已确立：全仓不得出现 `dangerouslySetInnerHTML`）。
4. **样式必须用行内 style 计算出的值**，不能直接把用户写的 `style` 字符串塞进 DOM 属性（那等于开了注入口子）。只认 `color` 与 `background-color` 两个属性，值必须匹配 `^#[0-9a-f]{6}$`（小写），否则不渲染。

## 4. 选区工具栏（p-editor）

**触发**：在编辑器内选中非空文本时，工具栏出现在**选区上方**。

**定位**：跟随选区；靠近窗口上边缘时翻到选区下方；左右夹紧不溢出。滚动/失焦/选区清空时隐藏。

**按钮**（顺序）：加粗 · 斜体 · 删除线 · 下划线 · 高亮 · 文字颜色▾ · 背景颜色▾ · 行内代码 · 链接 · 清除格式

- 颜色按钮是**下拉**（点开调色板）
- 每个按钮有 `aria-label` 与 `title`（含快捷键，如「加粗 (Ctrl+B)」）
- **切换语义**：选区已被该格式包裹 → 再点一次**取消**它
- 快捷键同时可用：`Ctrl+B` / `Ctrl+I` / `Ctrl+U`（下划线，新增）/ `Ctrl+E`（行内代码）/ `Ctrl+K`（链接，已有）

**边界**：

- **代码块内部**不弹工具栏（` ``` ` 围栏内的选区）
- 选区跨行时，只对**行内**格式生效；若选区跨越块级结构（标题/列表/表格），**降级为逐行包裹**或直接不显示，由 p-editor 决定并在回报里说明
- **触摸设备**：`(pointer: coarse)` 下工具栏改为**固定在视口底部**（手指点得到），最小 44×44

**体验**：工具栏不能遮挡选区本身；点击工具栏按钮**不得丢失编辑器选区**（用 `mousedown` + `preventDefault`）。

## 5. 删除笔记入口（f-shell）

**位置**：笔记列表项 —— 悬停时在右侧出现「⋯」按钮，点开菜单，含「**删除**」（危险色）。

**行为**：
1. 点「删除」→ 走 `ctx.confirm` 二次确认，文案说明「将移入回收站，可随时恢复」
2. 确认后调 `deleteNote(id)`（**必须用 `api/notes.ts` 里已有的那个函数**）
3. 成功 → 从列表移除；**若删的是当前打开的笔记，切到列表里的下一篇**；列表空了则显示空状态
4. 失败 → toast 报错，列表不变（不要乐观移除后不回滚）
5. **触摸设备**：列表项右侧操作**常驻可见**（不能依赖 hover），≥44×44

> 回收站已能恢复与彻底删除，本轮**不需要**改回收站视图。

## 6. 最近浏览接线（f-shell）

打开一篇笔记时调用 `recordNoteView(id)`。

**要求**：
- 同一篇**连续打开多次只记一次**（例如按 id 去重 + 会话内节流），避免刷屏
- **失败静默**（记录浏览不该影响主流程）
- 不能在每次重渲染时重复调用

## 7. 编辑器宽度（f-shell）

- `--editor-max` 由 **700/760px 提到 860px**（`tokens.css` 与 `shell.css:942` 的断点值都要改，保持一致）
- 顶栏新增**「宽屏 / 窄栏」切换**（图标按钮 + `aria-label`）：
  - 窄栏 = `var(--editor-max)`（860px）居中
  - 宽屏 = 占满可用宽度（`max-width: none`）
  - 选择持久化到 `localStorage`，刷新后保持
- **窄屏（≤1023px）下不需要这个按钮**（本来就没留白），隐藏即可
- **四断点不得产生横向溢出**

## 8. 搜索索引剥离内联 HTML（kb-note-api）

`search_blob` 当前是 `SearchText.normalize(title + " " + content)` —— **原始正文**。加了内联 HTML 后，`span`/`color`/`style`/`mark` 等词会进入全文索引，造成无意义的命中。

**要求**：构建 `search_blob` 前**剥离 HTML 标签**。`Excerpt.plain()` 已有一行 `replaceAll("<[^>]{1,200}>", " ")`（摘要早就在用），**复用同一套逻辑**，不要复制第二份实现。

**三处调用点**（`NoteService` 第 78 / 110 / 179 行）都要覆盖。

**回归要求**：既有 185 个测试全绿；新增测试至少覆盖「正文含 `<span style="color:#e11d48">文字</span>` 时，搜 `文字` 命中、搜 `color` / `span` 不命中」。

## 9. 导入缺图引导（kb-web-admin）

用户看到「20 张图片找不到 / 文件集合里没有这个路径」后**不知道该做什么**。

**要求**：
1. 缺图面板的文案要**说清原因与动作**，例如：
   「这些图片在你电脑上是有的，只是**这次没有被选中**。Markdown 里的图片是相对路径，浏览器无法自己去磁盘找 —— 请点下面的『改用选择文件夹』把 `images/` 目录一起选上。」
2. 面板里加一个 **「改用选择文件夹」** 按钮：点它直接打开文件夹选择器（`webkitdirectory`），**并把用户已有的选择清空**（避免两个来源混在一起）
3. **不得阻断导入**（现状已正确，保持）
4. 缺图明细保留（哪个文件、第几行、找的哪个路径、为什么）
