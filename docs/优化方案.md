# 知识库优化方案（2026-11-09）

> 一句话：功能已经够用。问题不在「缺功能」，而在**读起来累、手机上难用、改动没护栏**。
> 所以这份方案不新增业务功能，只做三件事：把阅读体验调舒服、把移动端补平、把工程护栏立起来。

---

## 0. 怎么用这份文档

- **依据全部是实测**，不是推测：三份只读审计（前端 36 项 / 后端 22 项 / 仓库 18 项，精确到 file:line）+ 历史资产（docs/test-20261027 的 26 条缺陷、docs/test-20261028 的 26/26 修复与性能 before→after、docs/页面优化方案.md）。
- **优先级口径**：`高` = 每天都会碰到，或会导致数据/部署事故；`中` = 特定场景明显受损；`低` = 有更好，没有不疼。
- **「立即」vs「排期」**：`立即` = 单文件/单变量级改动，10-30 分钟，能单独回滚；`排期` = 要改业务代码或要窗口期。
- **本文件只是方案**。除 §1.5 已获授权并完成的地基 5 项外，其余每一项开工前都会先跟你确认，再动手。
- **明确不做**：新增业务功能、SEO 重投入（理由见 §5.1）、更换部署形态（保持单机 + 临时隧道）。

## 3. 高优先级（8 项）

### H1 · 正文行宽与字号 — 立即

- **现状**：`--fs-base:14px`（tokens.css:27）+ `--editor-max:860px`（shell.css:962,1023），单行约 57 个汉字；宽屏模式不限制宽度（shell.css:967-970）。
- **做法**：`--editor-max` 860px → 680px；正文 `--fs-base` 14px → 15px；宽屏模式加 `max-width:90ch`。只动两个变量和一条规则，全在 `frontend/src/styles/`。
- **收益**：单行落到 40-45 个汉字（中文舒适区 30-45），长文回读少一次眼球回扫。
- **风险**：页面观感变窄；宽表格/长代码行横向滚动变多（已有 overflow-x，不会破版）。
- **验证**：1440 / 1920 各截一张含长段中文的笔记；DevTools 量 `.cm-content` 宽度 ÷ 汉字符宽；再开一篇含表格与长代码块的笔记确认不破版。
- **✅ 已实施**：见 §1.6。实测 860px→680px、单行约 61→45 汉字（1280×800 实拍对比）。

### H2 · 未登录首屏不再下载编辑器 — 立即

- **现状**：App.tsx:7 静态引 AppShell，AppShell.tsx:8 静态引 MarkdownEditor，导致首屏 modulepreload 里就带上含 EditorView 的 `dist-BjCbXaHj.js`（308 KB raw / 98 KB gzip）。
- **做法**：AppShell 内改成 `React.lazy(() => import('../editor/MarkdownEditor'))` + `Suspense` 骨架屏，只改两处 import。
- **收益**：未登录首屏 gzip 约 302 KB → 约 204 KB（-98 KB），弱网首屏少 1-3 秒。
- **风险**：首次进编辑器多一次 chunk 请求；懒加载失败要有兜底提示，否则是白屏。
- **验证**：未登录清缓存硬刷，Network 里不应出现含 EditorView 的 chunk；登录→新建笔记→编辑器与格式工具栏正常；`pnpm build` 后产物仍在 static 下。
- **✅ 已实施**：见 §1.6。首屏 gzip 297→105 KB（−65%）；笔记列表页只请求 3 个 assets，进详情才加载编辑器 chunk。

### H3 · sw.js 缓存版本改用单调 build id — 立即

- **现状**：sw.js:16-21 用 cache 名 `.sort().pop()` 取「字典序最大」当当前版本（:15 注释假设 stamp 是十六进制串），但 stampFromHtml(:25) 实际取的是内容哈希。新构建哈希若字典序更小，activate 会把刚写好的新 cache 当旧版删掉，导航回落仍是旧 shell。
- **做法**：构建时在 index.html 注入 `__BUILD_ID__`（时间戳），sw.js 读它当版本；或改成「保留最近两代」而不是按名字排序。
- **收益**：消除「部署后要手动清缓存 / 离线打开是旧版本或白屏」的隐性坑。
- **风险**：老 sw 的更新竞态要处理；上线后第一次访问会重装 cache。
- **验证**：连续两次 build 不同内容并部署，离线刷新能看到新版本；Application → Cache Storage 只剩当前与上一代；Service Workers 面板显示 activated and running。
- **✅ 已实施**：改动进了 `frontend/public/sw.js`（构建后复制到 static）。**离线冷启动这一条没在真机跑过**，需要你在浏览器里连续部署两次验证，见 §8 第 7 条。

### H4 · 备份轮转改按目录名判日期 — 立即

- **现状**：backup.ps1:86-96 按目录 `LastWriteTime` 判断 30 天轮转，16 份备份 mtime 全是 2026-10-28 16:50，其中包括今天那份 `kb-20261109-212350`。
- **做法**：从目录名解析 `yyyyMMdd-HHmmss`（前缀有 kb-/pre-opt-/pre-read-/pre-ui-/user-data- 五种），解析失败才退回 mtime。`scripts\lib\check.ps1` 已经用这个规则算「最新一份」，可直接复用同一段正则。
- **收益**：轮转不再批量误删；「最新备份是哪天」的判断终于可信。
- **风险**：脚本改错会误删 → 先加 `-WhatIf` dry-run，对比清单再真跑。
- **验证**：把一份旧目录 mtime 改成今天，dry-run 仍应判它过期；把今天那份 mtime 改成去年，也不应被判过期。
- **✅ 已实施 + 已实测**：见 §1.6。两个 2020 命名的目录被删，名字是今天而 mtime 是 2020 的那份保住了。

### H5 · 一条命令跑完整门禁 — 排期（0.5 天）

- **现状**：360 个 `@Test` 与 oxlint 没有任何自动执行点；kb-common.ps1:316 构建永远 `-DskipTests`；跑测试要手打 docs/README.md:234 那条带 5 个 JVM 参数的长命令；无 .github、无 CI。**且本机 `pnpm`、`mvn`、`corepack` 都不在 PATH**（只有 node v22.20.0）。
- **做法**：新增 `scripts\verify.cmd` → lib\verify.ps1，串三步：前端 lint → 后端 test → 可选前端 build，每步失败即停并给退出码。只读的 `check.cmd`（已落地）负责看状态，`verify.cmd` 负责跑门禁，两件事分开。
