# 知识库页面优化方案

> 基于 2026-11-01 的实际代码与界面核查编写。标「缺」的都是验证过当前不存在的。

## 零、先对齐四类页面

你的站不是博客，是「笔记应用」。所以这四个词要映射一下：

| 你说的 | 你站里的实际页面 | 路由 |
|---|---|---|
| 首页 | 笔记列表（全部笔记 / 最近浏览） | `#/notes` |
| 分类页 | 目录（folder）视图 + 标签视图 | 左栏目录树 / `#/tags` |
| 详情页 | 笔记视图（**编辑 + 预览一体**，不是纯阅读页） | `#/notes/:id` |
| 搜索结果页 | 搜索视图 | `#/search?q=` |

**这个差别很关键**：你的详情页默认是要编辑的，所以「阅读体验」优化必须**不跟编辑器打架** ——
凡是会占用正文宽度或打断输入的东西（目录锚点、阅读进度条）都得做成浮层或可关闭。

## 二、需要你先确认的 3 件事

1. **要不要对外公开某些笔记？**
   现在整站登录才可见，所有路由是 `#/hash`。这直接决定「SEO」这一项做不做、怎么做。
2. **主要用途是「写」还是「读」？**
   如果是写为主，详情页优化要克制（少占版面）；如果会反复回看旧笔记，才值得上大纲、进度、推荐。
3. **会不会多人用？** 现在有成员管理，如果只有你一个人，权限相关的状态设计可以极简。

## 三、关于 SEO 的实话

**当前架构下 SEO 基本无从谈起**，原因三条，缺一不可：

| 原因 | 说明 |
|---|---|
| hash 路由 | `#/notes/12` 里的 `#` 后面内容**不会发给服务器**，爬虫看到的是同一个空壳页面 |
| SPA 客户端渲染 | 首屏 HTML 里没有正文，搜索引擎拿到的是空 div |
| 全站登录墙 | 未登录一律跳登录页，爬虫进不去 |

所以「SEO 优化」在你的场景下**只有两个选择**：

- **选择 A（推荐，成本低）**：不做 SEO，改为做「**可分享**」—— 给某篇笔记生成一个带有效期的只读链接，
  发微信/邮件给人看。这一项收益远大于 SEO。
- **选择 B（成本高）**：真要公开，需要 ①改 history 路由 ②加服务端渲染或预渲染 ③单独做一套只读公开页 ④sitemap + robots。
  这是另一个项目的量级。

**我建议 A**。下面不给 SEO 项打优先级，等你确认后再说。

## 四、优化项（按优先级）

### 🔴 高优先级（直接影响「找得到、看得懂」）

#### H1. 面包屑（详情页顶部一行）
- **现状**：无。你打开一篇笔记，不知道它在哪个目录、从哪进来的。
- **改什么**：在笔记标题上方加一行 `全部笔记 / 技术博客 / 前端笔记`，每段可点。
- **规则**：根目录的笔记只显示「全部笔记」；从搜索点进来的显示 `搜索「关键词」 / 标题`。
- **收益**：任何时刻知道自己在哪、能一键回上一层。深目录下最明显。
- **工作量**：2 小时

#### H2. 详情页显示「创建 / 更新 / 版本」
- **现状**：无。你看不出这篇多久没改了、是不是旧版本。
- **改什么**：标题下方一行灰字：`创建 2026-10-12 · 更新 2 小时前 · 第 7 版`。
  「更新」用相对时间（刚刚/2 小时前/3 天前），悬停显示精确时间。
- **收益**：判断内容是否过时的第一依据。
- **工作量**：3 小时（后端已有 `updatedAt` 和 `version` 字段，只差前端展示）

#### H3. 搜索结果加「搜索历史」
- **现状**：无。每次都要重新打字。
- **改什么**：搜索框获得焦点且输入为空时，下方下拉显示最近 8 条历史（存 localStorage），带「清空」。
  点历史项直接填入并搜索。
- **收益**：重复查询成本从「打字」降到「一次点击」。
- **工作量**：3 小时

#### H4. 搜索输入防抖 + 联想词
- **现状**：无防抖，每敲一个字立刻请求。
- **改什么**：输入停顿 **250ms** 后才发请求；同时展示「可能的词」（取你标签库 + 标题里出现过的词），最多 5 个。
- **收益**：请求数下降一个数量级；打错字时能靠联想救回来。
- **工作量**：4 小时（防抖 1 小时，联想 3 小时）

#### H5. 上一篇 / 下一篇
- **现状**：无。
- **改什么**：笔记内容底部加两个左右并排的卡片：左侧「← 上一篇 标题」，右侧「下一篇 标题 →」。
  顺序 = 当前可见列表（已按目录筛选）的顺序。同时加 `Alt + ←/→` 快捷键。
- **收益**：按顺序读一组笔记时不用回列表。
- **工作量**：3 小时

### 🟡 中优先级（长文阅读 & 定位）

#### M1. 文章大纲（目录锚点）
- **现状**：无。长文（你有 9,500 字的笔记）只能滚。
- **改什么**：正文右侧（桌面 ≥1180px）显示一个浮动大纲，列出 `#/##/###` 标题，点一下平滑滚到对应位置；
  滚动时高亮当前所在小节。**宽度 ≤200px，可一键收起**，不挤压正文。
- **移动端**：不显示侧栏，改为顶部「目录」按钮 → 抽屉。
- **收益**：长文定位从「滚 + 靠眼力」变成一次点击。
- **工作量**：6 小时

#### M2. 阅读进度条
- **现状**：无。
- **改什么**：笔记视图顶部一条 2px 细线，随滚动填充。**只在滚动时才显示**（静止 1.5 秒后淡出），避免干扰编辑。
- **收益**：长文有「还剩多少」的心理预期。
- **工作量**：2 小时

#### M3. 相关推荐
- **现状**：无（只有反链，但反链要求你手动写过 `[[ ]]`）。
- **改什么**：在笔记底部「相关笔记」列出 3–5 篇，排序依据（都是现成数据，不用新表）：
  ① 共同标签数 → ② 同一个目录 → ③ 正文词频相似（用现有 FTS5 做关键词重叠）。
  **每条标注推荐理由**（`同标签：前端` / `同目录：技术博客` / `内容相近`），不要只给一串标题。
- **收益**：把「孤立的笔记」连成可发现的网络，这是知识库最大的价值点。
- **工作量**：8 小时

#### M4. 统一正文排版细节
- **代码块**：加语言标签（右上角小字）、复制按钮、横向滚动而不是折行。
- **表格**：窄屏下横向滚动 + 首列固定；斑马纹放在 hover 而非默认（降低视觉噪音）。
- **标题层级**：`#` 与 `##` 之间加更大的上边距，视觉上分段。
- **长段落**：正文行宽限制在 **~70 个汉字**（约 640px），太宽会读串行。
- **收益**：长文可读性最直接的提升，且不需要新功能。
- **工作量**：5 小时

#### M5. 标签体系补三样
- **现状**：标签页只列标签，没有分组和使用频率。
- **改什么**：①按使用次数排序 ②显示每个标签下的笔记数 ③支持「标签 + 目录」组合筛选。
- **收益**：标签多了以后还能用。
- **工作量**：4 小时

### 🟢 低优先级（打磨）

| # | 项 | 改什么 | 收益 | 工作量 |
|---|---|---|---|---|
| L1 | 键盘导航 | `g` 然后 `n` 跳到笔记列表、`/` 聚焦搜索、`?` 打开快捷键表 | 重度使用提速 | 4h |
| L2 | 笔记列表显示摘要 | 列表项加一行 60 字的正文摘要 | 不用点开就知道内容 | 2h |
| L3 | 批量操作 | 列表支持多选 → 批量移动目录/打标签/删除 | 整理迁移省力 | 8h |
| L4 | 统计可视化 | 现在统计页是数字，改成「写作热力图 + 标签分布」 | 知道自己写了什么 | 6h |
| L5 | 字体大小调节 | 编辑器 3 档字号（小/中/大），存 localStorage | 屏幕差异适配 | 2h |

## 六、交互状态设计

现在空状态组件已有（18 个文件在用），但另外四种状态覆盖不全：

| 状态 | 该怎么做 | 现在的状况 |
|---|---|---|
| **加载** | 骨架屏（列表用 3 行灰条），**超过 500ms 才显示**，避免闪烁 | 部分页面有，不统一 |
| **成功** | 轻量 toast（右下角，2 秒消失），**不要弹窗** | 有 toast |
| **失败** | 必须带**具体原因 + 下一步动作**。例：`保存失败：网络中断。已把内容存在本地，恢复后自动重试` +「重试」按钮 | 部分只显示「操作失败」 |
| **空** | 区分三种：① 真的没有（「还没有笔记，点右上角 + 新建」）② 筛掉了（「没有符合条件的结果 · 清除筛选」）③ 出错导致空（「加载失败，重试」） | 多数只做了第 ① 种 |
| **权限不足** | 现在多数是 403 静默失败。应显示「这篇笔记在你的空间里没有权限，切到有权限的空间或联系管理员」 | 缺 |

**统一原则**：任何超过 1 秒的操作都必须有反馈；任何失败都必须说明「为什么」和「我该做什么」。

## 七、桌面端 vs 移动端布局差异

| 区域 | 桌面（≥1180px） | 平板（900–1179） | 手机（<900，重点看 390） |
|---|---|---|---|
| 左栏目录树 | 常驻，宽 260px | 常驻，宽 220px | **抽屉**，点顶栏菜单滑出 |
| 笔记列表 | 左栏下方常驻 | 同左 | 独立一屏，进入笔记后隐藏 |
| 正文宽度 | 限 640px 居中 | 自适应 | 全宽，左右各 16px padding |
| 文章大纲 | 右侧浮层，可收起 | 收起，按钮唤出 | **不显示**，改顶部「目录」抽屉 |
| 相关推荐 / 上下篇 | 底部两列 | 两列 | **单列堆叠** |
| 搜索框 | 顶栏常驻 320px | 常驻 240px | 顶栏图标 → 展开成全屏搜索页 |
| 筛选条 | 一行横排 | 折两行 | 折成抽屉（底部弹出） |
| 主按钮（如一键获取） | 右上角常规尺寸 | 常规 | **全宽，高 ≥44px** |
| 表格 | 正常显示 | 横向滚动 | 横向滚动 + 首列固定 |
| 代码块 | 完整 | 横向滚动 | 横向滚动，字体缩到 13px |

**两条硬规则**：
1. 任何可点元素在手机上的**命中区 ≥44×44px**。
2. 390px 宽下**不允许横向滚动**（表格和代码块除外，它们自己滚）。

## 八、先做这 5 项（一周内可完成）

| 顺序 | 做什么 | 为什么先做这个 | 工作量 |
|---|---|---|---|
| 1 | **详情页加面包屑** | 成本最低、每次打开笔记都受益 | 2h |
| 2 | **详情页加创建/更新/版本一行** | 后端字段现成，纯前端渲染 | 3h |
| 3 | **搜索输入防抖 250ms** | 一行改动级别，立刻减少无效请求 | 1h |
| 4 | **搜索结果「筛掉了」和「没搜到」分开提示** | 现在混在一起，用户会以为内容不存在 | 2h |
| 5 | **上一篇 / 下一篇** | 按顺序读笔记的唯一入口，缺它很别扭 | 3h |

**合计约 11 小时**。做完这 5 项，日常使用的「迷路感」基本消失。

第二周可接：搜索历史（3h）+ 相关推荐（8h）+ 文章大纲（6h）。

## 九、不建议做的

| 想法 | 为什么不做 |
|---|---|
| 上 SEO / SSR | 全站登录墙 + hash 路由，改造成本远大于收益（除非你要公开分享） |
| 加「阅读模式」切换 | 你的编辑器本来就有实时预览，再加一个模式只会让人困惑 |
| 无限滚动加载列表 | 笔记是「找」不是「刷」，分页 + 搜索更合适 |
| 富文本工具栏做大做全 | 你是 Markdown 用户，工具栏越全越挡正文 |
| 详情页加侧边评论/批注 | 单人使用，没有收益 |
