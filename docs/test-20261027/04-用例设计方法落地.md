# 04 用例设计方法落地

> 教程第五章给了 8 种方法。本文记录它们在这个项目上的**具体落地**：用了哪张表、跑出什么结果、哪里方法不够用。推导表原文在各流 evidence 目录。

## 1. 从需求到用例的四步

1. **取事实**：E5 把 API.md / SCHEMA.md / README / 使用手册 与 197 个 Java 源文件、React 源码做三方比对，产出 **194 个测试点**（15 个模块）。
2. **选方法**：取值类→等价类/边界值；多条件→判定表；有生命周期→状态迁移；跨模块→场景法；攻击面→错误推测；多因素→正交。
3. **写判据**：每条用例的期望值必须可机判（状态码、JSON 字段、DB 值、耗时阈值）。
4. **执行并回填**：结论 + 实际值 + 证据指针；失败先过「是不是测试自己的错」这一关。

## 2. 等价类与边界值（投入产出最高的一组）

这个系统的边界特别密集，全部实测：

| 边界对象 | 精确边界 | 实测结论 |
|---|---|---|
| 单篇正文长度 | 2 MB（2,097,152 字节） | 恰好 2MB → 200；2.2MB → 400；5MB → 400；8.5MB 请求体 → 413（不 500） |
| 附件大小 | 20 MB | 20MB → 200（上传 553ms）；21MB → 413 |
| 附件类型 | MIME 白名单 | .html/.exe → 415；.svg 强制 attachment + nosniff |
| 标题长度 | 512 字 | 512 字 → 200；超长 → 400 |
| 用户名长度 | 3–32 位 | 2 位 → 400（E4 实测前端提示「用户名需 3–32 位」） |
| 密码长度 | ≥ 8 位 | 7 位 → 400 |
| 分页 size | 上限 100 | 超界被归一，不 500 |
| ZIP 条目数 | 2000 | **超过时提示「已拒绝整个压缩包」，实际写入了 2000 条**（缺陷 DEF-E2-001） |
| 中文检索词长 | 1 / 2 / 3 字 | 1 字「天」、2 字「天气」（短语精确）、3 字都能命中（单字检索是本系统卖点，实测成立） |

> 方法论提醒：**边界值在这个项目上命中了 1 条 S2**（ZIP 条目上限），而它在文档里写得清清楚楚——说明「文档有写」不等于「实现正确」，边界必须逐格验。

## 3. 判定表（角色 × 资源 × 操作）

E2 用 4 条身份 × 12 类资源 × 4 类操作构造判定表，重点验证「空间隔离」：

| 条件 | A 自己 | B 访问 A 的 | 不存在的 id |
|---|---|---|---|
| GET 笔记 | 200 | **404** | 404（响应体逐字相同） |
| PATCH / DELETE | 200 | **404** | 404 |
| 附件读/删 | 200 | **404** | 404 |
| 回收站恢复/彻底删 | 200 | **404** | 404 |
| 导出单篇 | 200 | **404** | 404 |
| 搜索命中 | 命中 | **0 条** | — |
| 管理接口 | admin 200 / 普通用户 403 | — | — |

结论：**28 条越权用例全部 404 且与不存在 id 的响应逐字一致**，没有存在性泄露。这是本系统最强的一处实现。

## 4. 状态迁移图

三台状态机被逐格验证：

| 状态机 | 合法迁移 | 实测 |
|---|---|---|
| 笔记生命周期 | 新建 → 编辑（版本+1）→ 软删 → 恢复 / 彻底删 | 全部正确；软删不改 updated_at（契约明文，实测一致）；恢复子目录只恢复祖先目录、祖先里的笔记保持删除（严格按 SCHEMA） |
| 版本历史 | 每次改动留历史快照；回滚产生新版本 | 快照数 = version-1（DB 级断言）；回滚后正文回到旧版且 version 递增；**但对「当前版本」回滚返回 404**（缺陷 DEF-E1-001，契约要求 no-op 200） |
| 邀请码 | 未使用 → 已使用；首人免邀请码 | 无邀请码/伪造邀请码 → 拒绝；空库首位注册者自动成为 admin 且**不下发会话**（需再登录） |

## 5. 场景法（端到端）

E4 用真实浏览器串了 12 条用户旅程，其中 3 条最能暴露问题：

- 新建 → 写正文 → 自动保存 → 刷新 → 内容一致 ✅（但**标题永远叫「未命名笔记」**，见 DEF-E4-001）
- 写 `[[标题]]` → 候选弹出 → 保存 → 跳转反链 ✅（唯一标题时正确；**同名多篇时只解析第一篇**）
- 历史版本 → 查看 → 回滚 → 二次确认 → 正文回退且版本+1 ✅

## 6. 错误推测（安全面）

| 推测 | 结果 |
|---|---|
| IDOR 遍历笔记 id 1..25 | **全部 404**，0 命中（守住） |
| FTS5 语法注入（12 组载荷） | **零命中**，无 SQL 报错（守住） |
| Markdown XSS（script/onerror/javascript:/iframe/svg） | 服务端原样存取、前端负责渲染；搜索高亮**已正确实体转义**；缺 CSP 兜底（DEF-E2-002） |
| 上传绕过（双扩展名/路径穿越/MIME 欺骗） | 服务端按 MIME 白名单 + 重命名，`../../evil.png` 只留 `evil.png`（守住） |
| Zip Slip（导入含 ../ 条目） | 逐条拒绝并记 errors（守住） |
| ZIP 炸弹/超量条目 | **命中**：2001 条目写 2000 条空笔记、提示却称已拒绝（DEF-E2-001，S2） |
| 账号枚举 | 文案与状态码完全一致、时序差 6ms（守住） |
| 暴力破解 | 连续失败 → 429（守住） |

> 这轮的规律与上个项目一致：**经典攻击面守得住，业务语义层的原子性/一致性容易失守**（导入非原子、同名解析歧义）。

## 7. 正交与负载模型（性能）

因素 = 接口（12）× 数据量（100/1000/10000 篇）× 并发档（10/25/50）。按「接口类别 × 数据量 × 并发」取代表组合，共 65 条 NF 用例，避免全组合的 12×3×3 次压测。

结论要点：读路径随数据量几乎不增长（列表 1 万篇 P95 26.7ms），但**搜索是例外**：

| 场景 | P95 |
|---|---|
| 1 万篇、正常正文、串行 | 289ms |
| 加入 1~2MB 正文后 | **1165ms**（删掉即回落 291ms） |
| 10 / 25 / 50 并发 | 3.6s / 8.2s / **14.4s**，吞吐恒定 ~15 rps |

## 8. 方法对比（本轮命中率）

| 方法 | 用例量级 | 命中缺陷 | 适用判断 |
|---|---|---|---|
| 边界值 | 高（≈40） | 2（ZIP 上限、正文 2MB 边界） | 便宜必做 |
| 判定表 | 中（≈30） | 0（空间隔离做得对） | 大面积确认「没问题」也是有价值结论 |
| 状态迁移 | 中（≈25） | 1（当前版本回滚 404） | 有生命周期的必须画图 |
| 场景法 | 中（≈68） | 5（界面/交互类） | 验收必需，缺陷命中率最低 |
| 错误推测 | 高（≈70） | 4（导入原子性、CSP、Secure、CSRF） | 安全面主力 |
| 正交/负载 | 中（≈65） | 6（性能类） | 性能主力 |

**组合原则**：先判定表建立「谁不能看谁」的骨架，再用边界值填输入格子，用状态迁移补生命周期，最后用场景法串旅程、错误推测补攻击面。不要从场景法开始。
