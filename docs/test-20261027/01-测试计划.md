## 一、测试目标

1. 在**不改动被测系统**的前提下，独立验证功能、边界、状态、权限、安全、性能、兼容七个维度。
2. 用教程规定的用例设计方法系统化产出用例（等价类、边界值、判定表、状态迁移、场景法、正交、错误推测）。
3. 产出可复现、有证据、有严重度与优先级的缺陷清单。
4. 给出能回答「这套系统现在能不能放心用」的度量与结论。

> 遵循第一原则：测试只能证明缺陷存在，不能证明系统无缺陷。结论表述为「在上述范围内未发现/发现 N 个问题」。

## 二、被测系统概述

## 四、测试策略

### 4.1 分层与分工

| 层 | 做法 | 执行者 |
|---|---|---|

### 4.2 用例设计方法映射（教程第五章）

| 方法 | 适用对象 | 承担 |
|---|---|---|
| 等价类划分 | 字段取值、ID 空间、文件类型 | E1、E2 |
| 边界值分析 | 20MB 上限、分页、标题/正文长度、1/2/3 字中文查询 | E1、E3 |
| 判定表 | 角色（admin/普通） × 资源（自己/他人） × 操作（读/写/删） | E2 |
| 状态迁移 | 笔记生命周期（草稿→保存→版本→软删→恢复/彻底删）、版本回滚、邀请码（有效/已用/过期） | E1 |
| 场景法 | 端到端：注册→建目录→写笔记→双链→搜索→回滚→回收站→导出→导入 | E4 |
| 正交实验法 | 并发档 × 数据量 × 接口类型 | E3 |
| 错误推测法 | IDOR 遍历、FTS5 语法注入、Zip Slip、Markdown XSS、超长字段 | E2 |

### 4.3 杀虫剂悖论对策

本项目已有 Java 测试套件。本轮**不以重跑既有断言为主要证据**：E1~E4 必须产出新增用例；既有套件只作回归基线（R16）。
