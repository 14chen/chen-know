## 2. S2 缺陷（5 条，逐条详解）

### DEF-E2-001 ｜S2/P1｜模块 IMPEXP
**标题**：导入不校验内容且非原子——空文件落成空笔记、超量 ZIP 一边说「已拒绝」一边写入 2000 条

| 项 | 内容 |
|---|---|
| 关联用例 | TC-IMPEXP-014（单文件）、TC-IMPEXP-201（2001 条目 ZIP） |
| 前置 | 任意登录账号；multipart 字段名 file |
| 复现 A（单文件） | 准备内容为空格与空行的 empty.md → POST /api/import/markdown → 响应 imported=1、skipped=0、errors=[] → 笔记列表多出一条空正文笔记 |
| 复现 B（超量 ZIP） | 构造 2001 个 0 字节 .md 的 zip → 同一接口 → HTTP **200**，imported=2000、skipped=0，errors 里却写「ZIP 条目数超过上限 2000，已拒绝整个压缩包」 → DB 实测新增 2000 条空笔记 |
| 期望 | 契约 §10.3：空文件计入 skipped 不落库；超 2000 条目整包拒绝、不产生任何笔记 |
| 实际 | 两者都落库；提示语与事实直接矛盾 |
| 证据 | evidence/e2/e2q-results-*.json、e2-raw3-*.log；evidence/e1/probe-2-import.log；**Lead 独立复验** evidence/lead/verify-final.log |
| 影响面 | 任何登录用户用 1KB 文件或百 KB ZIP 即可给自己的空间灌数千条空笔记；skipped 统计失去意义 |
| 复现率 | 3/3（E1）+ 2/2（E2）+ 1/1（Lead） |

### DEF-E3-001 ｜S2/P1｜模块 SEARCH/NOTE
**标题**：库内存在 1–2MB 正文的笔记时，全局搜索慢 4 倍

| 项 | 内容 |
|---|---|
| 关联用例 | TC-NF-019、054、060 |
| 复现 | 1 万篇 400 字笔记，GET /api/search?q=天 → P50 291ms；新建 1MB 与 2MB 正文（含「天气」）→ 同一查询 1165ms；删除这两篇 → 回落 291ms |
| 期望 | 单篇大文档不应把全局检索放大 4 倍 |
| 实际 | 1164.6ms；用 folderId 排除大笔记后 209ms；分页 size=10 仍 1153ms（与分页无关） |
| 证据 | evidence/e3/bignote-exp.log、search-attrib.log；**Lead 独立复验**（286KB 正文：82ms→123ms，方向一致） |
| 代码线索（只读） | SearchRepository 取 content 全文；notes.search_blob 无长度上限进 FTS5；SearchHighlighter 为每个命中行分配全文长度布尔数组并全量扫描 |
| 复现率 | 2/2（E3）+ 1/1（Lead 轻量复验） |

### DEF-E3-002 ｜S2/P1｜模块 SEARCH/NF
**标题**：并发下检索塌陷，整体吞吐恒定约 15 rps 不随并发增长

| 项 | 内容 |
|---|---|
| 关联用例 | TC-NF-049/050/051/055/056/057/058/064 |
| 复现 | 1 万篇 + 大正文存在，40s 固定并发：10 / 25 / 50 档 |
| 期望 | 50 并发混合 P95 不超过 3s，吞吐随并发近线性 |
| 实际 | P95 3,635 / 8,244 / **14,379ms**；P50 32/80/218ms；吞吐 13.5 / 15.3 / **15.5 rps**（50 并发仅为 10 并发的 1.15 倍）；单压搜索 10 并发 P50 3.1s、吞吐 2.5 rps，而列表 10 并发 317 rps |
| 证据 | evidence/e3/raw/concurrency.json、raw/attrib.json |
| 代码线索 | 搜索每请求两条重查询（search + count，均 JOIN notes_fts 且 bm25 排序）+ 每命中行全文高亮，无缓存 |
| 复现率 | 3/3 档位 |

### DEF-E4-001 ｜S2/P1｜模块 UI
**标题**：界面完全无法修改笔记标题——所有笔记永远叫「未命名笔记」

| 项 | 内容 |
|---|---|
| 关联用例 | TC-UI-019（稳定失败 3/3） |
| 复现 | 新建笔记 → 找任何改标题的入口 → 顶栏标题是不可编辑 SPAN、笔记项 hover 菜单只有「删除」、页内无标题输入框、双击无效 |
| 期望 | 可重命名（**API 明确支持** PATCH /api/notes/{id} 带 title） |
| 实际 | 无任何入口；新建时前端写死 title 为「未命名笔记」 |
| 证据 | evidence/e4/e4-a-results.json（TC-UI-019：菜单只有删除、标题输入框数 0）；**Lead 独立复验（代码级）**：API.md:139 支持 title，但前端 patchNote 仅用于 folderId / content / isFavorite |
| 影响面 | 命名、按名区分、搜索与双链的标题匹配全部受牵连；用户实际上无法给笔记起名 |
| 复现率 | 3/3 + 代码级确认 |

## 6. 修复建议排序（给开发）

1. **先修 S2 的三条数据/功能问题**：导入校验与原子性（E2-001）、笔记标题不可改（E4-001）、搜索被大正文拖垮（E3-001/002）。前两条是用户直接受损，第三条会随库增长越来越痛。
2. **再补契约与文档**：8 个 URI 登记（E5-002）、参数表与 SCHEMA（E5-003/004）、测试数口径（E5-005）——成本极低、收益极高，尤其 **E5-009 的 briefing 手动 run 口子**（应受 enabled 开关约束）。
3. **再优化**：统计聚合改一次查询（E3-003）、导入改批量事务（E3-004）、加 auto_vacuum 或提供 VACUUM 入口（E3-005）、引入连接池（E3-006）。
4. **顺手修**：当前版本回滚改 no-op 200（E1-001）、3 字高亮（E4-003）、删笔记后停止轮询（E4-004）、搜索页换正确端点（E4-005）、补 CSP / Referrer-Policy（E2-002）、Cookie Secure（E2-003）。
